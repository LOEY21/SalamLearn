1. Introduction
SalamLearn is an offline-first, interactive mobile educational application designed to augment the traditional
pedagogical methods of the Philippine Madrasah system. The mockups documented in this section align with
the Department of Education's (DepEd) Refined Elementary Madrasah Curriculum (ALIVE) for Grade 1
learners. To address localized constraints such as intermittent internet connectivity, restriction of classroom
devices to the educator only, and shared device usage at home, the underlying architecture relies on a local
caching framework (Hive) alongside a unified Flutter codebase.
This document presents high-fidelity mockups — rendered in the intended color palette and iconography —
for the primary screens of the system, and maps each screen to the functional requirement (FR) modules
defined in the system specification. Where a screen is used on more than one form factor, the phone and
monitor/tablet layouts are shown side by side in a single figure to make the responsive relationship explicit.

3. Visual Design Rationale
The mockups use the “Madrasah Classic” palette — a deep teal and warm gold on a cream base — chosen
to read as a school / madrasah product rather than a generic children's app, while remaining warm and legible
for learners aged 5–11 (NFR — Usability, ISO/IEC 25010 child HCI guidelines).

Teal is used for primary navigation and actions across all three actor experiences; gold marks rewards,
highlights, and the learner's identity elements (avatar, streak); coral is reserved for alerts and achievement
badges so it retains visual weight.

Figure 4.6 — Classroom cast screen, forced 16:9 landscape (monitor/TV only, no phone equivalent)
When the Teacher casts to an external projector or TV, the UI automatically scales and locks to 16:9
landscape so a single device can present to the whole class under a zero-student-device classroom model
(FR-6.4). This screen exists only in the cast/monitor form factor — the Teacher's own phone continues to
show the control screen from Figure 4.5 while this view is what the class sees. Hot Seat (FR-6.6) lets one
volunteer solve directly on the host device while classmates observe; the Choral controller (FR-6.7) triggers
whole-class repetition audio (Talqeen) without progression locks.

Figure 4.7 — Parental consent screen, shown during profile setup
Before a Learner profile can be created, the Parent must review a plain-language disclosure of what telemetry

5. Notes & Scope Exclusions
Module 4 — Core Educational Modules (FR-4.1–FR-4.5) is intentionally excluded from this mockup set.
Per the project team's specification notes, the specific game mechanics for this module (Tactile Recognition /
tracing engine, Pronunciation Audio Mapper, Qur'an/Hadith media playback controller, Sirah/Aqidah
storyboard, and the Fiqh/Taharah collision-and-array engine) are not yet finalized. Wherever a screen would
otherwise surface Module 4 content — the Student Hub lesson tiles (Figure 4.3) and the classroom cast
content area (Figure 4.6) — a generic placeholder is shown instead so the surrounding layout can still be
reviewed independently of the final game designs.
With the addition of Figures 4.7 and 4.8, every functional requirement module in the specification except
Module 4 now has a corresponding mockup: Module 1 (4.1), Module 2 (4.2, 4.7), Module 3 (4.3), Module 5
(4.4), Module 6 (4.5, 4.6), and Module 7 (4.8).
